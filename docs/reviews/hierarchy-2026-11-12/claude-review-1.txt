## Findings

**1. lib's test build depends on vendors, and the gate cannot see it (low to medium)**
- `lib/jwt/signing_test.go:22-23` imports `vendors/aws` and `vendors/gcp`; the file is in-package (`package token`, line 1) and uses `cloudaws.KMS` / `cloudgcp.KMS` at lines 59, 84, 123, 126.
- `tools/check_layers.py:188` skips every `*_test.go`, so `lib -> vendors` passes the gate.
- Consequences:
  - `go test ./lib/jwt` compiles the AWS and GCP KMS adapters, so "lib depends only on lib" holds for production files only.
  - `ALLOWED['vendors']` permits `vendors -> lib`. If `vendors/aws` or `vendors/gcp` ever imports `lib/jwt` (a natural edge for a KMS signer), the layer check stays green while `go test` fails with "import cycle not allowed in test".
- The same pattern exists one layer up: `vendors/mongodb/integration_test.go:20` and `body_integration_test.go:17` (`package mongo`, `integration` tag) import `procedures/event_stores/generic`.
- Smallest fix: move the two KMS cases next to the adapters or under `tests/`, or have the checker apply the lib rule to lib's `_test.go` files.

**2. Stale paths in current-owner docs (low, docs only)**

- No such import exists today, and the doc defers to the checker, so this is an unenforced claim rather than a violation.
